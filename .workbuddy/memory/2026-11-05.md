## 九、数据不自动更新（同日 11:10 追加修复）

用户问「为什么没有自动更新数据」。查下来是三个独立锁 + 一个松弛阈值：

1. **`latest_trade_date()` 缓存键错**（最严重）：`fetched == today` 就整天复用，
   而新浪日K盘中不返回当日那根 → 09:06 抓到的必然是昨天 → 写盘后**连收盘后也不重抓**，
   每天第一次抓取就把自己锁在昨天。改为 `td == today` 才锁定，否则三段 TTL 重试
   （盘中 5 分钟 / 收盘后 15:10~16:30 每 3 分钟 / 其余 30 分钟）。
2. **`_snapshot_load` 按 td 判磁盘新鲜**：td 一天只变一次 → 盘中快照永不重抓 →
   价格定格（实测 10:35 写盘后到 11:04 没动）。改为按 `ts`：盘中 60 秒、盘后 600 秒；
   `snapshot()` 内存 TTL 也跟时段走（盘中 20 秒 / 盘后 300 秒）。
3. **无定时器**：只在启动时 ensure_scan_async 一次。server 加常驻 `_auto_update`
   线程，60 秒幂等检查（榜单 trade_date vs latest_trade_date）。
4. **残页守卫 1000 绝对阈值太松**：盘前抓取过滤 price=0 后 2000 行能过线并写盘，
   而完整快照是 5572 行 → 全市场池缩水 2.8 倍且页面看不出来。
   加了相对判据 `< 上一份 70%` 也算残页。修好后强势股 58→76 只，
   战法预筛「K线不足」136→29。

重要语义（别搞错）：**「最近交易日」= 最后一根已收盘日K，盘中停在昨天是对的**。
要保证的是「价格随时在动 + 收盘后自动切到今天的K」，不是「盘中就显示今天」。

验证方法：`_snapshot_load()` 连调三次（第 2 次 disk-fresh、把 ts 拨旧 90 秒后第 3 次重抓 sina）；
`index.json` 现在带 `checked_ts`。快照已重建 5572 行，全市场重扫 5218 只、强势股 76 只。

  `app.isPackaged` 抛 TypeError，**进程闪退且零日志**。所有启动方式都要清掉它。

     `%LOCALAPPDATA%\electron-builder\Cache\<releaseName>\<文件名>`，构建器见到即跳过网络；

- 前端 `vendor/echarts.min.js` 原本缺失（加载器写着本地优先但文件不存在）→ 断网图表全空。

### 打包后发现并修掉的第五个缺陷：write_json 打开 .tmp 会失败

改为：payload 先序列化一次，临时名带 `pid.线程号`，打开+写入+replace 全部纳入重试（6 次退避）。
实测 20 线程并发写同一文件 0 失败、无残留 tmp。

## 十一、后台服务 + 自动更新（对齐 WorkBuddy 的三层架构）

### 架构切分
```
窗口（Electron）   随时可关，只负责显示
CoreService        常驻后台抓数/扫描/算榜单，监听 127.0.0.1:8092
updater            主程序退出后替换 exe（Windows 不允许替换运行中的 exe）
```
窗口启动先探 8092：服务在跑就复用（秒开零扫描），不在跑才自拉临时后端、关窗顺手停。
一份代码同时适配「装了服务」和「没装服务」。

### 新增文件
- `service.py`：**纯 ctypes 调 advapi32** 实现 SCM 宿主（StartServiceCtrlDispatcherW +
  RegisterServiceCtrlHandlerExW + SetServiceStatus），不要 pywin32/nssm/srvany。
  子命令 --install/--uninstall/--start/--stop/--status/--console/--run。
  服务模式数据写 `%ProgramData%\RightsideCompass`（LocalSystem 下程序目录可能只读），
  通过 COMPASS_STORE 传给 Python；`sc failure` 配了自动重启。
- `update_helper.py`：独立更新器。等主进程退出 → 校验 sha256 → 替换 → 重启。
  `--mode replace`（安装版覆盖）与 `--mode swap`（便携包换文件名启动新版 + 删旧版）。
- `release.py`：生成 latest.json（version/url/sha256/size/notes/force），支持 --publish。
- `update.json`：更新配置（feedUrl 留空 = 不检查更新，默认关闭防误报）。
- `install_service.bat` / `uninstall_service.bat`：自动提权后调 service.py。

### main.js 新增
- `checkUpdate()`：启动后延迟 10s 静默检测；菜单/托盘「检查更新…」；`--self-update --force`
  命令行入口（不需要窗口，装完退出）。
- `doUpdate()`：下载（标题栏显示进度）→ sha256 校验 → 移交 update_helper（detached）。
  校验通过且 `COMPASS_UPDATE_DRY_RUN=1` 时只报告不替换（自测 + 排障用）。
- 便携包必须用 `PORTABLE_EXECUTABLE_FILE` 定位「自己」——`process.execPath` 指向临时解压目录。

### 已验证（全部通过）
- 更新链路：本地 http.server 当更新源，1.0.0 → 远端 1.0.1，日志
  `版本比对: 本地 1.0.0 远端 1.0.1` → 下载 81484741 bytes → `sha256 校验通过` → DRY-RUN 跳过。
  重复运行走「复用已下载的更新包」；远端 1.0.0 时不下 载。

## 十二、坐标系自检页：把「验证结论」从写死改成数据驱动（2026-11-05 下午）

### 起因
`index.html` 第 396043 起有 704 字符的固定文案，句句是人工写死的判断。重跑 edge 后
数据变了，文案没跟着变，页面在说反话。**更隐蔽的是取了错字段**：卡片标题写「超额」，
数值却取 `h10` / `h5`（绝对收益）—— 下跌样本里两者会反号。

实测（state/edge.json，3997 样本 / 400 只池 / 10 验证日）：

| 分档 | n | T+5 超额 | T+10 超额 | T+10 绝对 |
|---|---|---|---|---|
| 可介入 | 421 | −0.06% | **+0.21%** | −0.88% |
| 观察 | 2482 | +0.11% | +0.20% | −1.12% |
| 回避 | 1094 | −0.23% | **−0.53%** | −1.82% |
